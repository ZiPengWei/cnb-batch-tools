# CNB 批量合并工具 (CNB Batch Merge Tool)

这是一个基于 **Electron** + **Vue 3** 构建的桌面应用程序，旨在帮助开发者高效地在 [CNB (cnb.cool)](https://cnb.cool) 仓库中执行多分支批量合并操作，简化发布流程中的分支管理。

## ✨ 主要特性

- **现代精密工作台界面**: 采用「曜石青蓝（深色）/ 云岩微雾（浅色）」双模配色与一体化无缝三栏布局（macOS 融入红绿灯无边框顶栏），支持搜索子序列关键词高亮、仓库主名与命名空间分层展示、分支前缀语义微色与仿真骨架屏。
- **外观模式自由切换**: 默认跟随系统浅色/深色模式，也支持在顶栏一键切换「跟随系统 / 深色 / 浅色」并本地记住。
- **网页账号登录（免令牌）**: 默认使用网页账号登录，应用内嵌 CNB 登录窗（自动唤起微信扫码），无需手动创建令牌；登录会话自动持久保存，启动时自动恢复连接，已连接后顶栏认证面板自动收起释放工作区空间。
- **访问令牌（可选）**: 也支持 CNB 访问令牌（Access Token）鉴权，可在"网页登录 / 访问令牌"之间一键切换；支持切换账号与退出登录。
- **仓库置顶双向同步**: 仓库列表支持置顶/取消置顶（独立分组展示），操作实时写回 CNB 服务端，与 CNB 网页端置顶状态自动同步。
- **源分支按提交时间排序**: 分支列表立即展示、立即可选，提交时间排序在后台计算完成后平滑更新，选择大仓库无需等待。
- **智能分支管理**:
  - 自动识别并置顶核心环境分支（`dev`, `test`, `gray`），支持一键「核心环境」快选。
  - 支持多选目标分支、「全部 / 已选」切换视图、全选当前筛选结果与一键清空，一次性将代码合并到多个环境。
  - **记住上次工作现场**: 关闭窗口重开或重启应用后，自动恢复上次的仓库、源分支与目标分支选择，无需重新勾选。
  - 与源分支同名的目标分支自动禁用，防止误选。
- **全流程键盘快捷键**:
  - `Ctrl/Cmd+F` 按当前焦点列智能聚焦过滤框，`Ctrl/Cmd+1/2/3` 直达仓库/源分支/目标分支过滤框，`Esc` 清空过滤词；
  - 列表内 `↑/↓` 移动高亮、`Enter` 选择仓库/源分支、`空格` 勾选目标分支、`Ctrl/Cmd+A` 全选当前、`Shift+点击` 区间连选目标分支；
  - `Ctrl/Cmd+Enter` 就绪时直接拉起合并确认弹窗，弹窗内再按 `Ctrl/Cmd+Enter` 直接确认提交。
- **清晰的操作与结果反馈**:
  - 底部发车确认坞直观展示 `仓库 | 源分支 → 目标分支` 流水线，支持直接在胶囊上点 `×` 移除或点击 `+N` 弹出管理全部目标。
  - 顶栏「最近合并历史」时间线随时可查并支持**一键回填**历史仓库/源分支/目标分支组合；确认合并弹窗同样展示当前仓库的上次合并与最近历史。
  - 合并进行中实时解析日志，逐个点亮目标分支状态（等待 / 进行中 / 成功 / 冲突 / 无变更 / 失败）并附进度条与深色等宽终端日志。
  - 合并结果按成功、冲突、失败、无变更 4 格统计概览 + 分类明细展示，附 PR 直达链接，可一键复制纯文本报告，冲突/失败项支持"仅重试失败"。
  - 合并完成后发送系统通知（点击唤起主窗口），批量合并时切走也不错过结果。
  - 分支列表加载失败时自动诊断原因：网页登录已过期会提示重新登录，仓库被改名/移动/删除或无权限会提示刷新仓库列表，不再显示原始报错。
- **登录过期主动提醒**: 登录会话失效后弹出提示框询问是否重新登录，同意后自动打开 CNB 登录窗口，重新登录成功即恢复使用。
- **合并进行中退出保护**: 批量合并运行时关闭窗口/退出应用会先确认，防止误操作中断合并。
- **独立批量合并**: 每个目标分支独立处理，互不影响：
  - 无变更 → 自动跳过。
  - **检测到冲突 → 跳过该分支并自动取消（关闭）对应 PR**。
  - 无冲突 → 直接合并。
  - 结束后汇总提示：哪些分支冲突、哪些分支成功合并。
- **实时日志反馈**: 在合并过程中实时展示操作日志，方便追踪进度和排查错误。
- **窗口大小与位置记忆**: 关闭窗口重开或重启应用后，自动恢复上次的窗口大小与位置，无需每次重新调整。
- **Windows 托盘最小化**: Windows 下关闭窗口时可选择"最小化到系统托盘"或"直接退出"，支持勾选"记住我的选择"；偏好可在界面"关闭窗口时"设置中随时修改，托盘图标支持单击恢复主界面、右键退出。
- **应用内一键更新**: 发现新版本后可直接在应用内下载（带 sha256 完整性校验与进度显示），Windows 下载完成后一键自动替换并重启；macOS 自动挂载安装镜像并替换应用（无需手动处理 Gatekeeper 拦截），应用在任意位置运行（包括从安装镜像内直接运行）都会静默完成更新并自动安装到「应用程序」文件夹，全程无需手动拖拽；极端情况下自动降级为打开 Release 页/所在文件夹手动完成。
- **自动检查更新**: 应用启动后自动检查 GitHub 最新 Release，有新版本时版本号旁显示红点角标并提示；仅提示、不强制更新。

## 📦 下载与安装

从 [Releases](https://github.com/ZiPengWei/cnb-batch-tools/releases/latest) 页面下载对应平台的产物：

- **Windows**: `CNB-Tools.exe`，单文件便携版，下载后双击即可运行，无需安装。
- **macOS**: `CNB-Tools.dmg`，打开后将 `CNB-Tools.app` 拖入「应用程序」文件夹。

### macOS 提示「已损坏，无法打开」？

本应用暂未进行 Apple 开发者签名与公证，较新版本的 macOS 会拦截**浏览器下载**的未签名应用，并提示「"CNB-Tools"已损坏，无法打开」。这不是文件真的损坏，属于 Gatekeeper 对未签名应用的拦截行为。在终端执行以下命令解除隔离标记即可正常打开：

```sh
xattr -dr com.apple.quarantine /Applications/CNB-Tools.app
```

- 仅首次安装或每次更新覆盖后需要执行一次，执行后该副本不会再弹窗。
- 若应用未放在「应用程序」，请将命令中的路径替换为 `.app` 的实际所在路径。

## 🚀 开发环境设置

### 前置要求

- **Node.js**: 建议版本 v18 或更高
- **包管理器**: 推荐使用 [pnpm](https://pnpm.io/) (本项目使用 `pnpm` 进行依赖管理)

### 1. 安装依赖

```bash
pnpm install
```

### 2. 启动开发模式

此命令将同时启动 Vite 开发服务器和 Electron 应用窗口，支持热更新。

```bash
pnpm dev
```

### 3. 构建应用

构建生产环境的发布包：macOS 为 `.dmg`，Windows 为**单文件便携 `.exe`**（无需安装，下载即用）。

```bash
pnpm build
```

产物输出至 `release/{version}/`：`CNB-Tools.dmg`、`CNB-Tools.exe`（文件名不含平台与版本号，版本体现在输出目录与 Release 上）。

### 4. 运行测试

运行单元测试以确保功能正常。

```bash
pnpm test
```

### 5. ESLint（Airbnb Base + Vue）

本项目使用 ESLint 做静态检查，规则集以 Airbnb JavaScript Base 为基础，并叠加 Vue 3 推荐规则与部分模板最佳实践规则。

```bash
pnpm lint
pnpm lint:fix
pnpm check
```

配置文件说明：

- 由于本项目 `package.json` 设置了 `"type": "module"`，ESLint 传统配置文件使用 `.eslintrc.cjs`（而不是 `.eslintrc.js`）以避免 ESM/CJS 加载冲突。

规则定制决策（与现有代码风格兼容）：

- `quotes` / `semi` 关闭：当前项目存在单双引号与分号风格混用，避免首次引入 ESLint 造成大面积改动。
- `import/no-unresolved` 关闭：在 TS + Vue SFC + bundler 模式下，解析 `.vue` 与部分构建期路径时更适合交给 TypeScript/Vite 处理，避免误报。
- `no-underscore-dangle` 关闭：Electron 主进程中使用 `__dirname` 等写法较常见。
- `vue/multi-word-component-names` 关闭：允许 `App` 等单词组件名。

IDE/编辑器建议（以 VS Code 为例）：

- 安装扩展：ESLint（dbaeumer.vscode-eslint）
- 启用保存自动修复（用户/工作区设置均可）：

```json
{
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": true
  },
  "eslint.validate": ["javascript", "typescript", "vue"]
}
```

开发集成：

- `pnpm dev` 会通过 Vite 插件在开发过程中执行 ESLint 检查并输出问题（终端/覆盖层提示）。

## 📖 使用指南

1.  **登录 CNB 账号（默认网页登录）**: 启动应用后默认为"网页登录"模式，点击登录按钮会打开 CNB 登录窗（自动唤起微信扫码），登录成功后自动返回应用，认证面板自动收起（随时可点顶栏右上角账号胶囊展开切换账号或改用令牌）。
2.  **选择仓库**: 从左列选择要操作的仓库（主名高亮 + 命名空间弱化显示），支持模糊搜索高亮；鼠标悬停可点击置顶（与 CNB 网页端双向同步）或在浏览器中直达仓库。
3.  **选择源分支**: 在中间列选择源分支（Source Branch），列表按最近提交时间倒序排列并带分支类型微色标识。
4.  **选择目标分支**: 在右列多选目标分支（Target Branches），可使用「★ 核心环境」一键勾选 `dev/test/gray`、「全选当前」（或 `Ctrl/Cmd+A`）、「全部 / 已选」视图切换、`Shift+点击` 区间连选或点击「清空」；上次为该仓库选择的目标分支会自动恢复。
5.  **执行合并**: 在底部发车确认坞核对 `仓库 | 源分支 → 目标分支`（可直接点胶囊 `×` 移除或点 `+N` 管理全部目标），点击「合并」或按 `Ctrl/Cmd+Enter` 打开确认弹窗后执行；也可点顶栏时钟图标一键回填历史合并组合。
6.  **查看结果**: 合并进行中实时点亮各目标分支状态并推进终端进度条；结束后弹出结果窗口，展示 4 格统计概览，默认展开冲突与失败明细，成功、无变更明细及操作日志可展开查看：
    - ✓ 成功合并的分支
    - ✗ 存在冲突被跳过（PR 已自动取消）的分支
    - 失败/无变更的分支及原因

例如：`fix-1` 分支同时合并到 `dev` 和 `test`，若 `dev` 存在冲突，则跳过 `dev` 并取消其 PR，`test` 无冲突则直接合并；最终提示“存在冲突已跳过的分支: fix-1 -> dev”、“成功合并的分支: fix-1 -> test”。

### 关闭窗口行为（Windows）

Windows 下关闭窗口时会询问"最小化到系统托盘"还是"直接退出"，勾选"记住我的选择，不再询问"后按所选行为执行、不再弹窗；之后可随时在认证卡下方的"关闭窗口时"下拉中修改。最小化到托盘后程序在后台运行，单击右下角托盘图标（或右键选择"打开主界面"）即可重新打开窗口，右键菜单中可选择彻底退出。macOS 关闭窗口即为标准的"隐藏窗口、程序保留"，点击 Dock 图标恢复。

### 访问令牌方式（可选）

若不便使用网页登录，可在认证卡的"访问令牌"页签改用令牌鉴权：登录 [cnb.cool](https://cnb.cool) → 个人设置 → 访问令牌，创建包含以下权限的令牌：

- `account-profile:r`（验证令牌）
- `account-engage:r`（获取仓库列表）
- `repo-code:r`（获取分支、比较差异）
- `repo-pr:rw`（创建/合并/取消 PR）

两种方式可在认证卡右上角随时切换；已连接令牌的用户默认展示令牌面板。也可在此切换账号（重新拉起登录窗，切换成功前不影响当前账号信息）或退出登录。

## 🔌 CNB Open API 说明

应用通过 [CNB Open API](https://api.cnb.cool/) 与 CNB 交互，主要接口映射：

| 功能 | API |
|---|---|
| 验证令牌 | `GET /user` |
| 仓库列表 | `GET /user/repos?role=Developer`（分页） |
| 分支列表 | `GET /{repo}/-/git/branches`（分页） |
| 无变更预检 | `GET /{repo}/-/git/compare/{base...head}` |
| 创建 PR | `POST /{repo}/-/pulls` |
| 查询 PR（含冲突状态） | `GET /{repo}/-/pulls/{number}` |
| 查询已存在 PR | `GET /{repo}/-/pulls?state=open&base_ref=...` |
| 合并 PR | `PUT /{repo}/-/pulls/{number}/merge` |
| 取消（关闭）PR | `PATCH /{repo}/-/pulls/{number}` `{state: closed}` |
| 仓库置顶（读） | `GET /user/repos` 返回 `pinned` / `pinned_time` 字段 |
| 仓库置顶（写回） | `POST/DELETE https://cnb.cool/user/dashboard/pinned-stars/{repo}`（需网页会话 Cookie 认证） |

冲突判定基于 PR 的 `mergeable_state`（`conflict`）与 `blocked_on`（`code_conflict`）字段。

## 🎨 UI 规范：统一设计系统与 Naive UI 干净用法

- 设计系统配色与控件 Token 由 `src/renderer/ui/theme.ts`（深色「曜石青蓝」/ 浅色「云岩微雾」）及 `src/style.css` 集中维护，通过 `n-config-provider` 的 `theme-overrides` 统一注入，禁止覆写 `cls-prefix` / `namespace` / `breakpoints`。
- 禁止在任意 `n-*` 组件标签上直接散写静态 `class` / `style` / `size` 属性；统一从 `src/renderer/ui/naive.ts` 按需导入 Naive UI。
- 自动检查：运行 `pnpm test`（或 `pnpm check`）会包含使用规范检查用例，确保没有遗漏。
